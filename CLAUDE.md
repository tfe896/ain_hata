# Як ми працюємо: лендінги AIN (загальні правила для всіх клієнтів)

Цей файл читається на початку кожної сесії. Тут лише те, що однаково для всіх проєктів: головні принципи, етапи по порядку, технічні домовленості. Спілкування з користувачем — українською.

**Специфіка клієнта** (id у Figma й Webflow, айдентика, правила саме цього проєкту) лежить у `<client>-landing/CLAUDE.md` і `README.md`. Перед роботою з клієнтом прочитати обидва. Зараз: `mazda-landing/`, `godlike-landing/`. Нового клієнта створюємо командою `python3 shared/new_client.py <name> <prefix> "<Назва>"` (див. «Репозиторій і нові клієнти»).

## Головні принципи (не забувати)
1. **Дизайн і тексти лише з матеріалів клієнта.** Нічого не додавати від себе: тексти, факти, маршрути, назви беремо з тексту авторки й матеріалів. Сумнів — питати.
2. **Усе проходить через Figma.** Мудборд (за замовчуванням), потім дизайн-концепт. Коментарі правок лишаються у Figma, я читаю їх сам через REST API і виправляю, а не приймаю правки з чату.
3. **Макет одразу «під Webflow»**, збірка нативними елементами, код анімацій усередині Webflow (файли в Assets).
4. **Перевіряю сам і чесно кажу межі перевірки.** Локальна емуляція (Playwright) і жива сторінка; що видно лише на справжньому пристрої (iPhone Safari, дрижання на тачпаді), віддаю користувачу.
5. **Сторінка читається без скрипта.** Запобіжник-клас із таймером, `prefers-reduced-motion`, скрол ніколи не блокується.
6. **Спільне робимо спільним.** Загальні інструменти й блоки лежать у `shared/`, а не в папці клієнта.
7. **Робота з git:** коміт і push у гілку сесії; pull request лише за проханням користувача; жодних згадок моделі в комітах. Секрети (токени) ніколи не просити в чат: тільки через форму `request_credential`.

## Етапи по порядку
Кожен наступний етап не починаємо, доки не завершено попередній. Для кожного: що робимо → де інструмент → коли готово.

1. **Бриф.** Мета, аудиторія, тексти (або структура), бренд (лого, кольори, шрифти), фото, відео, референси, побажання щодо анімацій. На старті спитати: тариф сайту Webflow, файли шрифтів клієнта, чи правитиме код анімацій хтось із команди без мене (відкрите питання, див. нижче). Готово: матеріали зібрані, джерела й відкриті питання записані в `README.md` клієнта.
2. **Мудборд** (2–3 напрями на вибір): палітра, шрифтові пари, приклади композицій, настрій фото, графіка/3D, мотиви анімацій. У Figma (плагіном) або HTML-артефактом для швидкого погодження. Клієнт обирає один напрям. Правки: коментарі у Figma → я читаю через API → виправляю. Виняток тільки якщо користувач каже, що вихідний макет уже є (так було на Mazda: макет зробила дизайнерка). Готово: напрям обрано.
3. **Дизайн-концепт у Figma на основі обраного напряму**, одразу «під Webflow»: Auto Layout скрізь; назви шарів = класи Webflow (з префіксом проєкту); фрейми Desktop 1440 і Mobile 390; змінні кольорів, текстові стилі Desktop/Mobile, компоненти для повторюваних блоків; рожеві мітки анімацій (`data-anim`, `data-count`…) поруч із макетом і сторінка «Інструкція Webflow». Будується **повним генератором-плагіном** (працює в будь-якому файлі), який користувач запускає у Figma Desktop. Після кожного запуску я знімаю рендер через API і перевіряю сам.
4. **Погодження макета.** Коментарі дизайнера/клієнта у Figma (з координатами) → зводжу в таблицю правок → правлю → знову рендер. Готово: «подобається».
5. **Збірка у Webflow нативними елементами** (Section/Heading/Paragraph/Image/Link) з тими ж класами; стилі класів дублюються у Webflow, щоб Designer показував дизайн. Шрифти, картинки, відео, карти — у Assets (API без Designer). Класи кожного проєкту мають префікс. Готово: сторінка збирається, прибрані зайві/осиротілі класи.
6. **Анімації й 3D** — див. «Як обирати спосіб анімації» та «Код анімацій у Webflow».
7. **Кінцевий блок** (титри + «Читайте також» + футер AIN) — обов'язковий, див. нижче.
8. **Перевірка й публікація.** Прогін `shared/qa/` (мобільна версія, заставка, паралакс, живий футер), публікація (раз на хвилину), перевірка живої сторінки (скрипти на місці, хеші, відсутні посилання на GitHub). Готово: користувачу віддано те, що можу перевірити лише не я.
9. **Передача.** Інструкція для команди (що правиться у Webflow без коду, що заміною файлу; шаблон — `mazda-landing/TEAM-GUIDE.md`), пам'ятка редакторам клієнта, оновлені README і `CLAUDE.md` клієнта, коміт і push.

## Як обирати спосіб анімації (єдина структура: об'єднання підходу колег і нашого)
1. **Прості** (поява блоків при скролі, hover, паралакс, sticky, прогрес скролу, меню): нативні Webflow Interactions, редактори бачать і правлять їх у Designer. Спершу перевірити, що вміє `data_interactions_tool`; чого не вміє, те скриптом або короткою інструкцією.
2. **Середні й складні** (текст по літерах і словах, лічильники, бігучі рядки, заставка, карта, 3D, WebGL, шейдери): код-файли в Webflow Assets із версією в назві. GSAP + ScrollTrigger (cdnjs) беремо, лише якщо команда підтвердить, що правитиме код сама (питання відкрите); інакше легкий власний JS без залежностей.
3. **Що беремо від нас:** контракт `data-` атрибутів, префікс класів проєкту, запобіжник-клас із таймером, `prefers-reduced-motion`, мобільні правила, перевірка емуляцією, історія в git.
4. **Що беремо від колег (Artycoders):** нативні Interactions для простого, версії файлів у назві (`-v1`, `-v2`, відкат поверненням старого файлу), код у Webflow, дружній до експорту, BEM-подібні назви класів (`stat-card_value`, `is-light`).

### Контракт анімацій
- Скрипт знаходить елементи лише за `data-` атрибутами та класами проєкту, тому редактори вільно міняють тексти, цифри, посилання й фото.
- Спільні атрибути: `data-anim="lines|letters|words|scrub|reveal"`, `data-count` (лічильник), `data-video` + `data-video-mobile`, `data-fallback`; проєктні (як `data-shot`, `data-map`, `data-scene`) описані в `CLAUDE.md` клієнта.
- Кожен крок скрипта ізольований (`step(name, fn)`), помилки в консоль із префіксом проєкту; на `<html>` ставиться клас `<prefix>-js` (стилі анімацій тільки під ним), запобіжник знімає його через 5 с, якщо скрипт не виставив `window.__<name>Ready`.
- Короткі слова (й, і, у, в, з, на…) не лишаються в кінці рядка (неразривний пробіл).

## Код анімацій у Webflow (як це робиться)
- **Рішення користувача:** з наступних проєктів увесь код усередині Webflow. Джерело коду лежить у репозиторії, у Webflow живуть **зібрані файли в Assets** з версією в назві: `<name>-style-vN.js` (head: запобіжник, шрифти, стилі) і `<name>-anim-vN.js` (кінець body: логіка), підключені зареєстрованими hosted-скриптами з SRI. На опублікованій сторінці жодних посилань на GitHub/jsDelivr; відео, карти й інші файли теж у Assets.
- Порядок оновлення: правка джерела → `shared/qa/` → `python3 shared/webflow-tools/build_files.py …` → `create_asset` ×2 → `shared/webflow-tools/wfup.py` → звірити md5/sha384 з CDN → `register_hosted_script` ×2 (нова версія, SRI) → `set_page_scripts` → Publish → записати версію в README клієнта. Відкат: повернути попередню версію скриптів.
- Godlike лишається як є (Embed зафіксований на коміті, не ламати). Mazda: обидві версії (jsDelivr і автономна) збережені.

## Кінцевий блок усіх лендінгів (рішення користувача)
- Усі лендінги закінчуємо тим самим блоком: титри («Дизайн та верстка — Made by vibecoder Taras 🤖») + «Читайте також» з 4 картками + футер AIN (панель із колонками). Плашку партнера не додаємо, поки користувач не скаже.
- У фінальній версії змінюються **лише статті для перелінковки** (4 картки: посилання, заголовок, підзаголовок, партнер, тег, картинка 2:1). Титри, панель AIN, посилання й юридичний текст не міняємо.
- Джерело: `shared/ain-footer/` (`cards.json`, шаблон, стилі, картинки, генератор `build_footer.py`, README у `shared/`). Назви й теги карток я складаю сам із заголовків статей, тому перед публікацією показую їх користувачу.

## Мобільна версія, заставка й продуктивність (уроки)
- На телефонах і планшетах не робимо паралаксу й `scale`-анімацій від скролу (iOS «дихає» висотою вікна з адресним рядком, фото смикаються); перший екран у `svh`, а не `vh`.
- Паралакс від скролу, який рахується в JS, відстає від прокрутки на кадр і дає дрижання навіть на десктопі: для дрібних фото (полароїди, картки) його не робимо; великим фото лише легкий.
- Відео першого екрана: окрема легка вертикальна версія для телефона (`data-video-mobile`), постер до першого кадру.
- Заставка: колір завіси видно з першого кадру (шар-заглушка в стилях до старту скрипта), інакше сторінка миготить; завіса з ефектом удару більша за екран на запас трясіння; перед стартом чекаємо на шрифт лічильника (не довше ~1,2 с).
- Після змін перевіряти емуляцією iPhone: зсув елементів при скролі вниз-вгору, горизонтальне переповнення, старт відео.

## Репозиторій і нові клієнти
- `CLAUDE.md` (цей файл) — тільки загальне. `shared/` — спільні інструменти й блоки (див. `shared/README.md`): `webflow-tools/` (збірка файлів, завантажувач у Webflow), `qa/` (перевірки), `ain-footer/` (кінцевий блок), `client-template/` і `new_client.py` (старт нового клієнта).
- Кожен клієнт: папка `<client>-landing/`, окрема гілка, окрема сесія; свої `CLAUDE.md` і `README.md`. Префікс класів кожного проєкту унікальний на сайті Webflow (Mazda — `mz-`, Godlike — `gl-`).
- Репозиторій — джерело коду (правки й збірка). Зміни в `shared/` не повинні ламати вже опубліковані проєкти. Плагін Figma: база в `figma-plugin/` (Godlike) і `mazda-landing/figma-plugin/`; копіювати й адаптувати.
- У корені лежать старі сторонні файли (png, `.tmj`): не чіпати.

## Обмеження інструментів (перевіряти на старті)
- **Figma MCP на плані Starter** має дуже малий ліміт викликів. Тому макети будуються **локальним плагіном**, який користувач запускає у **Figma Desktop**: Plugins → Development → Import plugin from manifest (у веб-версії локальні плагіни не запускаються). Плагін віддавати архівом із `manifest.json` і `code.js`; нагадувати розпакувати повністю («An error occurred while loading the plugin environment» найчастіше означає, що поруч із маніфестом немає `code.js`). З платним планом можна напряму через MCP.
- Середовище `ain_hata` має збережений токен Figma (лише читання): макет, коментарі з координатами й рендери читаються через REST API (`api.figma.com/v1/files/<key>/…`) без ліміту MCP. Плагін для користувача — завжди повний генератор (не правки по id шарів).
- Середовище відкриває Google Drive: публічну папку читаємо через `drive.google.com/embeddedfolderview?id=<id>`, файли — `drive.usercontent.google.com/download?id=<id>&export=download&confirm=t`.
- **Мережа:** дозволені хости задаються в середовищі; потрібний хост додаємо через `update_environment` (користувач підтверджує). Нині дозволені також сторінки колег і сайт Webflow, який перевіряємо вживу.
- **Webflow Data API** працює без Designer: сторінки, вставка HTML/CSS як рідних елементів (`data_whtml_builder`: один кореневий елемент; CSS лише правила класів і брейкпоінти 991/767/479; без `@keyframes`; `target` у посилань не зберігає, виставляти `set_attributes`; зовнішні `src` картинок ігнорує, прив'язувати `set_image_asset`), атрибути, стилі, ассети (`create_asset` + POST у S3 через `shared/webflow-tools/wfup.py`; приймає `.js`, `.mp4`, `.svg`, `.webp`), шрифти (`create_font`), публікація (раз на хвилину). **Вільний кастомний код API не пише** (`set_page_freeform_code`, `add_page_script` → 404): тільки зареєстровані скрипти (`register_hosted_script` з SRI; inline ≤ 2000 символів; максимум 15 скриптів на сторінку; існуючий скрипт не оновлюється, реєструємо нову версію) + `set_page_scripts`. Знімки екрана Webflow — лише з відкритим Designer.
- **Класи Webflow спільні для всього сайту**: на одному сайті кілька лендінгів, тому префікс обов'язковий.
- **Інструмент Bash:** вбудована перевірка безпеки може хибно блокувати довгі команди з heredoc або видаленням; тоді файли пишу інструментом Write, тестую у тимчасовій теці сесії і нічого не видаляю без потреби.

## Як працює команда AIN у Webflow (розібрано з їхніх сторінок)
- `special.ain.ua/...` — **експорт Webflow** (відносні `css/`, `js/`, `images/`), статика на їхньому сервері + GTM. Скрипти, зареєстровані у Webflow, в експорті лишаються абсолютними посиланнями на CDN Webflow.
- Анімації: GSAP + ScrollTrigger (cdnjs) + Lenis (unpkg), невеликі читабельні inline-скрипти в Custom code сторінки, прості ефекти — нативні Interactions; запобіжник `anim-ready` (4 с) і `prefers-reduced-motion`. Великий код — `.js` у Assets із версією в назві (`gl-3d-v9.js`). Класи на кшталт BEM/Client-First.
- Спільний футер AIN (`ainf-*`, скрипт `footer-v2/ain-footer.js`): наш аналог — `shared/ain-footer/`. Зразок: `ain-x-godlike.webflow.io`.
