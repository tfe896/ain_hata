# Як ми працюємо: лендінги AIN (мудборд → Figma → Webflow → анімації з GitHub)

Цей файл читається на початку кожної сесії. Тут зафіксований процес і технічні домовленості, на яких тримаються наші лендінги. Спілкування з користувачем — українською.

## Процес для нового клієнта
1. **Бриф.** Мета, аудиторія, тексти (або структура), бренд (лого, кольори, шрифти), фото, референси, побажання щодо анімацій.
2. **Мудборд** (2–3 напрями на вибір): палітра, шрифтові пари, приклади композицій, настрій фото, 3D/графіка, мотиви анімацій. Робиться у Figma (плагіном, див. нижче) або як HTML-сторінка-артефакт для швидкого погодження. Клієнт обирає один напрям. Правки до мудборду теж лишаються коментарями у Figma: я читаю їх через REST API (з координатами) і виправляю, а не приймаю правки з чату. Виняток: на Mazda цей етап пропущено, бо вихідний макет уже зробила дизайнерка (її коментарі були вхідними правками). Для нових проєктів мудборд за замовчуванням потрібен, якщо користувач не скаже, що вихідний макет уже є.
3. **Дизайн-концепт у Figma на основі обраного мудборду**, одразу «під Webflow»:
   - Auto Layout скрізь; назви шарів = класи Webflow (`sec`, `wrap`, `split`, `col`, `fig`, `glass`, `stat`, `card`, `cta` …);
   - фрейми Desktop 1440 і Mobile 390; змінні кольорів, текстові стилі Desktop/Mobile, компоненти для повторюваних блоків;
   - рожеві мітки анімацій (`data-anim`, `data-count`, `data-scene` …) поруч із макетом + сторінка «Інструкція Webflow».
4. **Погодження** макета клієнтом у Figma (коментарі → правки).
5. **Збірка у Webflow нативними елементами** (Section/Heading/Paragraph/Image/Link) з тими самими класами; стилі класів дублюються у Webflow, щоб Designer показував дизайн. Шрифти — у Site settings → Fonts. Картинки — в Assets (потрібен відкритий Designer з додатком Webflow MCP).
6. **Анімації й 3D** — **з наступних проєктів усе всередині Webflow** (рішення користувача): джерело коду в репозиторії, у Webflow живуть зібрані файли в Assets із версією в назві (`<client>-anim-v1.js`, `<client>-style-v1.js`), підключені зареєстрованими hosted-скриптами з SRI (Webflow API не пише вільний кастомний код, але приймає `.js` як ассет); короткі скрипти можна лишати inline. Скрипт знаходить елементи лише за `data-` атрибутами, тому редактори вільно міняють тексти, цифри, посилання й фото. Відео, карти й інші файли теж у Webflow Assets, а не на jsDelivr. Повна схема (збірка, завантаження, хеші, відкат) і готові скрипти: `mazda-landing/site/webflow/build_standalone.py` (режим `files`), `mazda-landing/README.md`, розділ «Автономна версія».
7. **Перевірка** (локальна імітація опублікованої сторінки, мобільна версія, FPS), публікація, коротка пам'ятка для редакторів клієнта.

## Як обирати спосіб анімації (єдина структура для всіх нових лендінгів: об'єднання підходу колег і нашого)
1. **Прості** (поява блоків при скролі, hover, паралакс, sticky, прогрес скролу, меню): нативні Webflow Interactions, редактори бачать і правлять їх у Designer (як у колег). Спершу перевірити, що вміє `data_interactions_tool`; чого не вміє, те скриптом або короткою інструкцією.
2. **Середні й складні** (текст по літерах і словах, лічильники, бігучі рядки, заставка, карта, 3D, WebGL, шейдери): код-файли в Webflow Assets із версією в назві (див. крок 6). GSAP + ScrollTrigger (cdnjs) беремо, лише якщо команда підтвердить, що правитиме код сама (питання відкрите, користувач уточнює); інакше легкий власний JS без залежностей.
3. **Що беремо від нас:** контракт `data-` атрибутів, префікс класів проєкту (`mz-`, `gl-`…), запобіжник-клас із таймером (сторінка читається без скрипта), `prefers-reduced-motion`, мобільні правила (нижче), перевірка емуляцією, історія в git.
4. **Що беремо від колег:** нативні Interactions для простого, версії файлів у назві (`-v1`, `-v2`, відкат поверненням старого файлу), код у Webflow, дружній до експорту (посилання на CDN Webflow лишаються в експорті), BEM-подібні назви класів (`stat-card_value`, `is-light`).
5. Godlike лишається як є (Embed зафіксований на коміті, не ламати). Mazda: обидві версії (jsDelivr і автономна) збережені.

На старті проєкту спитати: тариф сайту Webflow, файли шрифтів клієнта, чи мають редактори клієнта правити самі анімації.

## Структура репозиторію для нових проєктів
- Кожен клієнт — окрема папка в корені (`<client>-landing/`), окрема гілка, окрема сесія. Репозиторій лишається джерелом коду (правки й збірка), але на опублікованій сторінці посилань на GitHub/jsDelivr бути не повинно.
- Спільне (адаптер, плагін Figma, генератори) копіювати з `godlike-landing/` і `figma-plugin/` та адаптувати, не ламаючи робочий лендінг Godlike (його Embed зафіксований на коміті).

## Обмеження інструментів (перевіряти на старті)
- **Figma MCP на плані Starter** має дуже малий ліміт викликів. Тому макети будуються **локальним плагіном** (`figma-plugin/`), який користувач запускає у **Figma Desktop**: Plugins → Development → Import plugin from manifest. У веб-версії Figma локальні плагіни не запускаються. З платним планом (Professional, Dev/Full seat) можна працювати прямо через MCP.
- **Webflow**: Data API (сторінки, вставка HTML/CSS як рідних елементів, атрибути, стилі, публікація) працює без Designer. Картинки й шрифти теж можна залити без Designer: `create_asset` / `create_font` + POST файлу в S3, потім `set_image_asset` на елементі (вставка HTML сама картинки не прив'язує). Код сторінки підключається зареєстрованими скриптами (`register_*_script` + `set_page_scripts`); `set_page_freeform_code` і `add_page_script` на сторінці без коду повертають 404. Знімки екрана — лише з відкритим Designer.
- **Класи Webflow спільні для всього сайту**: на одному сайті кілька лендінгів, тому класи кожного проєкту мають свій префікс (Mazda — `mz-`).
- Мережа сесії не відкриває webflow.io: опубліковану сторінку перевіряє користувач, а ми робимо локальну імітацію.

## Технічний контракт анімацій (godlike-landing — перший проєкт за цією схемою)
- `js/webflow-native.js` — адаптер: перетворює звичайний текст з Webflow на розмітку анімацій (літери, слова, лічильники, бігучі рядки, меню, полотна фігур). Кожен крок ізольований, помилки пишуться в консоль як `[godlike]`.
- `js/app.js` + `js/shaders.js` — анімації й WebGL-фігури. Плавний скрол колесом вмикається лише поки працює головний цикл (скрол ніколи не блокується).
- Атрибути: `data-anim="letters|words|scrub|reveal"`, `data-count`, `data-scene="N"`, `data-stream`, `data-marquee="l|r"`, `data-menu="Назва"`, `data-fallback` (у картинок).
- Градієнтні слова — `<span class="gt">` всередині тексту.
- Оновлення коду: коміт → новий хеш у п'яти посиланнях Code Embed → Publish.
- Інструменти: `godlike-landing/webflow/mknative.js` (чиста розмітка з HTML), `build_webflow.py` (секції + CSS для класів Webflow), `native-test.html` (локальна перевірка), `figma-plugin/` (генератор макета у Figma).

## Що користувач високо оцінив у Mazda (зберігати як стандарт)
- Я сам заходжу у Figma через REST API, читаю коментарі дизайнерки з координатами, зводжу їх у таблицю правок і виправляю; після кожного запуску плагіна знімаю рендер і перевіряю.
- Дизайн-концепт будується повним генератором-плагіном за повним текстом авторки, нічого не вигадуючи, одразу «під Webflow» (назви шарів = класи, Desktop/Mobile).
- Заливка у Webflow без Designer: сторінка нативними елементами, ассети, шрифти, стилі класів, атрибути `data-*`, скрипти, публікація; перевірка локальною імітацією (Playwright), а те, що можна побачити лише на справжньому пристрої, чесно віддаємо користувачу.

## Мобільна версія й продуктивність (уроки Mazda)
- На телефонах і планшетах не робимо паралаксу й `scale`-анімацій від скролу (iOS «дихає» висотою вікна з адресним рядком, фото смикаються); перший екран у `svh`, а не `vh`.
- Відео першого екрана: окрема легка вертикальна версія для телефона (`data-video-mobile`), постер до першого кадру.
- Після змін перевіряти емуляцією iPhone: зсув елементів при скролі вниз-вгору, горизонтальне переповнення, старт відео.

## Де лежить код анімацій: GitHub чи Webflow (рішення в роботі)
- Основний варіант: код у репозиторії, у Webflow посилання на jsDelivr із зафіксованим комітом і SRI. Запасний: автономна версія (`mazda-landing/site/webflow/build_standalone.py`, сторінка `/mazda-spivpratsia-standalone`): мінімізований код, розрізаний на ≤15 скриптів по ≤2000 символів, бо API не дозволяє вільний кастомний код.
- Остаточне рішення залежить від того, як сторінка потрапляє на сайт замовника (проксі, експорт, iframe) і чи є обмеження на сторонні скрипти (CSP). У команди замовника вже є своя схема роботи через Webflow: коли користувач скине їхній дизайн-концепт і сторінку на їхньому сайті, вивчити її й працювати за тією ж стратегією.

## Як працює команда AIN у Webflow (розібрано з їхніх сторінок, середовище дозволяє special.ain.ua, ain-x-godlike.webflow.io, cdn.prod.website-files.com)
- `special.ain.ua/...` — **експорт Webflow** (відносні `css/`, `js/`, `images/`), статика на їхньому сервері + GTM. Скрипти, зареєстровані у Webflow, в експорті лишаються абсолютними посиланнями на `cdn.prod.website-files.com`.
- Анімації: GSAP + ScrollTrigger (cdnjs) + Lenis (unpkg), невеликі читабельні inline-скрипти в Custom code сторінки, прості ефекти — нативні Webflow Interactions; запобіжник `anim-ready` (4 с) і `prefers-reduced-motion`.
- Великий код — .js-файли в Webflow Assets із версією в назві (`gl-3d-v9.js`, `defer`), спільний футер AIN вставлений inline (`footer-v2/ain-footer.js`). Класи на кшталт BEM/Client-First (`stat-card_value`, `is-light`).
- Інструкція для команди (що правити у Webflow без коду, що заміною файлу): `mazda-landing/TEAM-GUIDE.md`; технічні кроки для мене: `mazda-landing/README.md`, розділ «Автономна версія».
- Рішення користувача: на Mazda лишаємо обидві версії (GitHub/jsDelivr і автономну з шматків) без змін. У наступних проєктах пробуємо робити так само, як колеги (команда Artycoders): код файлами в Webflow Assets із версією в назві, прості ефекти нативними Interactions, більше схожості з їхнім процесом. Чи правитиме наш код хтось у команді без мене, поки не відомо (користувач уточнює).

## Уроки щодо Figma (перевірено на Mazda)
- Середовище `ain_hata` має збережений токен Figma (лише читання): макет, коментарі з координатами й рендери читаються через REST API (`api.figma.com/v1/files/<key>/…`) без ліміту MCP. Після кожного запуску плагіна користувачем знімати рендер і перевіряти самому.
- Плагін для користувача — завжди повний генератор, що працює в будь-якому файлі (не правки по id шарів): його запускають і в інших файлах, і на іншому комп'ютері.
- Віддавати архівом із `manifest.json` і `code.js`; нагадувати розпакувати повністю. Помилка «An error occurred while loading the plugin environment» найчастіше означає, що поруч із маніфестом немає `code.js` (точна причина — у Console).

## Спільний футер AIN у лендінгах колег (Artycoders)
- На кінці їхніх сторінок один і той самий готовий блок із класами `ainf-*` (обгортка `.ain-footer`): плашка партнера («Матеріал підготовлено за підтримки …» + лого + «Що це означає?»), титри («Дизайн та верстка — Artycoders»), «Читайте також» з 4 картками інших спецпроєктів (картинка webp, тег «Спецпроєкт», партнер, заголовок, підзаголовок; посилання на `special.ain.ua`) і футер AIN (лого, колонки «AIN / Співпраця / Соцмережі / Правила», юридичний текст).
- Це звичайні елементи Webflow плюс спільний скрипт `footer-v2/ain-footer.js` (близько 8,5 КБ): вставляє стилі (стрілки SVG, hover, перехід картинок), відкриває всі посилання в новій вкладці з `rel=noopener` (і для елементів, доданих пізніше), поява при скролі, `prefers-reduced-motion`. Зразок розмітки: `ain-x-godlike.webflow.io` (кінець сторінки).
