# Як ми працюємо: лендінги AIN (мудборд → Figma → Webflow → анімації з GitHub)

Цей файл читається на початку кожної сесії. Тут зафіксований процес і технічні домовленості, на яких тримаються наші лендінги. Спілкування з користувачем — українською.

## Процес для нового клієнта
1. **Бриф.** Мета, аудиторія, тексти (або структура), бренд (лого, кольори, шрифти), фото, референси, побажання щодо анімацій.
2. **Мудборд** (2–3 напрями на вибір): палітра, шрифтові пари, приклади композицій, настрій фото, 3D/графіка, мотиви анімацій. Робиться у Figma (плагіном, див. нижче) або як HTML-сторінка-артефакт для швидкого погодження. Клієнт обирає один напрям.
3. **Дизайн-концепт у Figma на основі обраного мудборду**, одразу «під Webflow»:
   - Auto Layout скрізь; назви шарів = класи Webflow (`sec`, `wrap`, `split`, `col`, `fig`, `glass`, `stat`, `card`, `cta` …);
   - фрейми Desktop 1440 і Mobile 390; змінні кольорів, текстові стилі Desktop/Mobile, компоненти для повторюваних блоків;
   - рожеві мітки анімацій (`data-anim`, `data-count`, `data-scene` …) поруч із макетом + сторінка «Інструкція Webflow».
4. **Погодження** макета клієнтом у Figma (коментарі → правки).
5. **Збірка у Webflow нативними елементами** (Section/Heading/Paragraph/Image/Link) з тими самими класами; стилі класів дублюються у Webflow, щоб Designer показував дизайн. Шрифти — у Site settings → Fonts. Картинки — в Assets (потрібен відкритий Designer з додатком Webflow MCP).
6. **Анімації й 3D** — код у цьому репозиторії, підключається одним Code Embed унизу сторінки через jsDelivr із зафіксованим комітом. Скрипт знаходить елементи лише за `data-` атрибутами, тому редактори вільно міняють тексти, цифри, посилання й фото.
7. **Перевірка** (локальна імітація опублікованої сторінки, мобільна версія, FPS), публікація, коротка пам'ятка для редакторів клієнта.

## Як обирати спосіб анімації
1. **Прості** (поява блоків при скролі, hover, паралакс, sticky, прогрес скролу, меню): рідні Webflow Interactions, редактори бачать і правлять їх у Designer. Спершу перевірити, що вміє `data_interactions_tool`; чого не вміє, те зробити скриптом або дати користувачу коротку інструкцію.
2. **Середні** (текст по літерах і словах, лічильники, бігучі рядки, магнітні кнопки, курсор): невеликий скрипт у Code Embed на сторінці (працює й на безкоштовному тарифі сайту), керований `data-` атрибутами.
3. **Складні** (3D, WebGL, шейдери, великі скрипти): код у цьому репозиторії, підключення через jsDelivr із зафіксованим комітом.

На старті проєкту спитати: тариф сайту Webflow, файли шрифтів клієнта, чи мають редактори клієнта правити самі анімації.

## Структура репозиторію для нових проєктів
- Кожен клієнт — окрема папка в корені (`<client>-landing/`), окрема гілка, окрема сесія.
- Спільне (адаптер, плагін Figma, генератори) копіювати з `godlike-landing/` і `figma-plugin/` та адаптувати, не ламаючи робочий лендінг Godlike (його Embed зафіксований на коміті).

## Обмеження інструментів (перевіряти на старті)
- **Figma MCP на плані Starter** має дуже малий ліміт викликів. Тому макети будуються **локальним плагіном** (`figma-plugin/`), який користувач запускає у **Figma Desktop**: Plugins → Development → Import plugin from manifest. У веб-версії Figma локальні плагіни не запускаються. З платним планом (Professional, Dev/Full seat) можна працювати прямо через MCP.
- **Webflow**: Data API (сторінки, вставка HTML/CSS як рідних елементів, атрибути, стилі, публікація) працює без Designer. Картинки й шрифти теж можна залити без Designer: `create_asset` / `create_font` + POST файлу в S3, потім `set_image_asset` на елементі (вставка HTML сама картинки не прив'язує). Код сторінки підключається зареєстрованими скриптами (`register_*_script` + `set_page_scripts`); `set_page_freeform_code` і `add_page_script` на сторінці без коду повертають 404. Знімки екрана — лише з відкритим Designer.
- **Класи Webflow спільні для всього сайту**: на одному сайті кілька лендінгів, тому класи кожного проєкту мають свій префікс (Mazda — `mz-`).
- Мережа сесії не відкриває webflow.io: опубліковану сторінку перевіряє користувач, а ми робимо локальну імітацію.

## Технічний контракт анімацій (godlike-landing — перший проєкт за цією схемою)
- `js/webflow-native.js` — адаптер: перетворює звичайний текст з Webflow на розмітку анімацій (літери, слова, лічильники, бігучі рядки, меню, полотна фігур). Кожен крок ізольований, помилки пишуться в консоль як `[godlike]`.
- `js/app.js` + `js/shaders.js` — анімації й WebGL-фігури. Плавний скрол колесом вмикається лише поки працює головний цикл (скрол ніколи не блокується).
- Атрибути: `data-anim="letters|words|scrub|reveal"`, `data-count`, `data-scene="N"`, `data-stream`, `data-marquee="l|r"`, `data-menu="Назва"`, `data-fallback` (у картинок).
- Градієнтні слова — `<span class="gt">` всередині тексту.
- Оновлення коду: коміт → новий хеш у п'яти посиланнях Code Embed → Publish.
- Інструменти: `godlike-landing/webflow/mknative.js` (чиста розмітка з HTML), `build_webflow.py` (секції + CSS для класів Webflow), `native-test.html` (локальна перевірка), `figma-plugin/` (генератор макета у Figma).

## Уроки щодо Figma (перевірено на Mazda)
- Середовище `ain_hata` має збережений токен Figma (лише читання): макет, коментарі з координатами й рендери читаються через REST API (`api.figma.com/v1/files/<key>/…`) без ліміту MCP. Після кожного запуску плагіна користувачем знімати рендер і перевіряти самому.
- Плагін для користувача — завжди повний генератор, що працює в будь-якому файлі (не правки по id шарів): його запускають і в інших файлах, і на іншому комп'ютері.
- Віддавати архівом із `manifest.json` і `code.js`; нагадувати розпакувати повністю. Помилка «An error occurred while loading the plugin environment» найчастіше означає, що поруч із маніфестом немає `code.js` (точна причина — у Console).
