# Godlike.host × AIN — лендінг

Статичний сайт без збірки. Одна й та сама папка працює двома способами:
1. **Окремо** (Vercel або будь-який статичний хостинг): відкривається `index.html`.
2. **Усередині Webflow** через один Embed (див. нижче).

## Структура
```
index.html          розмітка (секції #s1…#end, меню, шапка); єдине джерело тексту
css/style.css       усі стилі; змінні кольорів і шрифтів на початку (:root); в кінці блок сумісності з Webflow
js/app.js           уся поведінка, розділена коментарями-заголовками:
                    intro · sections/layout · reveal · scroll effects · wheel smoothing ·
                    menu · glass/CTA · hero data stream (WebGL) · 3D figures (WebGL, GPU time budget) · main loop
js/shaders.js       шейдер 3D-фігур (по одній сцені на блок, номер сцени = data-scene)
js/webflow-mount.js підключає лендінг на сторінку Webflow (тягне index.html, css, скрипти)
webflow-embed.html  код, який вставляється в Embed у Webflow
vercel.json         дозволяє Webflow-сторінці завантажувати файли з цього хостингу (CORS)
assets/             шрифти Gilroy, фото, логотипи, logo_sdf16.png (дані для 3D-логотипа)
```

## Webflow: як підключити
Найпростіше, коли файли лишаються на хостингу (Vercel), а в Webflow вставляється короткий Embed.

1. Задеплойте цю папку на Vercel як статичний сайт (Framework Preset «Other», без build-команди). Перевірте, що `https://ВАШ-ДОМЕН/index.html` відкривається.
2. У Webflow створіть порожню сторінку. У Body не повинно бути відступів (padding 0), ніяких інших елементів.
3. Додайте Embed (Add elements → Components → Embed) прямо в Body, вставте вміст `webflow-embed.html` і замініть `YOUR-DOMAIN.vercel.app` на ваш домен (двічі). Домен із `https://` і слешем в кінці.
4. Заголовок, опис, OG-картинку задайте в Page settings сторінки Webflow.
5. Збережіть і опублікуйте. У Designer Embed не виконується, дивитися треба в Preview або на опублікованому сайті.

Обмеження:
- Текст лендінгу підвантажується скриптом, тому в Webflow його не можна редагувати в Designer, а пошукові системи бачать лише оболонку сторінки. Для сторінки, якій потрібне SEO, потрібна нативна збірка з елементів Webflow (окрема робота).
- Лендінг залежить від доступності хостингу (Vercel). Якщо змінюєте домен, змініть його й в Embed.
- Стилі лендінгу глобальні (класи `.top`, `.menu`, `.cta`, `.card` тощо). На сторінці з цим лендінгом не додавайте елементи Webflow з такими самими іменами класів.

## Де що міняти
- **Текст:** `index.html`. Заголовки розбиті на `<span class="c">` по літерах, абзаци на `<span class="wd">` по словах (для анімації появи). Щоб змінити текст, замініть літери всередині спанів зі збереженням структури, або залиште звичайний текст (анімація літер для нього зникне).
- **Кольори, відступи, розміри шрифтів:** `css/style.css`, блок `:root`.
- **Посилання кнопок «Create Server»:** `index.html`, пошук `godlike.host`.
- **Фото:** `assets/`, підключені в `index.html` через `background-image`.
- **Анімації появи:** у CSS блок «text + block reveals»; запускаються класом `.in`, який додає `js/app.js`.
- **3D-фігури:** камера на сцену в `CAM` у `js/app.js`; форми й матеріали в `js/shaders.js` (функція `map0`, `if(S==N)`).
- **Форми:** на сторінці лише кнопки-посилання; форми заявки немає.

## Примітки
- Без JavaScript увесь контент видимий (приховування для анімацій вмикає сам скрипт).
- Поважає `prefers-reduced-motion`.
- На пристроях без WebGL2 фігури не відображаються, решта сторінки працює; потік даних на першому екрані тоді малюється легшим 2D-варіантом.

## Продуктивність (60 кадрів/с)
- Потік даних на першому екрані (WebGL, на весь екран) рахується на відеокарті: процесор лише передає кілька десятків чисел за кадр.
- Кадр кожної 3D-фігури розбивається на смуги, які малюються на сусідніх кадрах сторінки, тож відеокарта не блокує скрол і потік. Скільки смуг потрібно, сторінка вираховує сама: вартість кадру фігури вимірюється один раз у спокої (де браузер дозволяє, постійно уточнюється таймером відеокарти), ще не виміряні фігури оцінюються за виміряними. На сильній відеокарті кадр фігури — одна смуга, фігура оновлюється кожен кадр; на слабшій фігура просто оновлюється рідше, а сторінка лишається плавною.
- Роздільність і якість країв не знижуються першими. Лише якщо кадр однієї фігури коштує понад ~57 мс (оновлення рідше ніж 15 разів на секунду), сторінка по одному кроку зменшує кількість променів згладжування, а далі — щільність пікселів до 1.5×.
- Фігури не крутяться вільно: у спокої вони лише ледь помітно «дихають» (усередині сцени рухаються діоди, вентилятори, підсвітка), при наведенні нахиляються на кілька градусів, при перетягуванні повертаються до ~30° і після відпускання плавно повертаються у початкове положення. Скрол фігури не обертає, тому під час скролу вони перемальовуються рідше.
- Шейдери збираються наперед у вільний час (не під час інтро і не під час скролу).
- Перший екран: «потік даних» натискається й утримується (заряджається), відпускання надсилає ударні хвилі крізь потік і літери заголовка.
