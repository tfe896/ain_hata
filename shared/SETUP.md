# Доступ до Figma, Webflow і мережі: налаштування нового середовища Claude Code

Правила роботи (етапи, анімації, кінцевий блок) лежать у репозиторії, а **доступи ні**: вони зберігаються в налаштуваннях середовища конкретного акаунта Claude. Новий акаунт чи нове середовище треба налаштувати один раз за цією інструкцією. Секрети (токени) **ніколи не кладемо в репозиторій і не пишемо в чат**.

## 1. Figma: читання макета, коментарів і рендерів
Мета: Claude сам читає макет і коментарі дизайнера з координатами та знімає рендери через REST API, без ліміту Figma MCP.

1. **Створити токен** (робить власник Figma-акаунта): Figma → аватар → Settings → Security → Personal access tokens → Generate new token. Права тільки на **читання**: File content, File metadata, Comments, Current user (за потреби Library content / File versions). Запису не давати.
2. **Передати токен Claude лише через захищену форму:** сказати Claude «потрібен токен Figma», він викличе `request_credential` для хоста `api.figma.com`, заголовок `X-Figma-Token` (префікс не потрібен). Значення вводиться у формі, Claude його не бачить. Токен зберігається в середовищі як мережевий секрет, і проксі підставляє його в запити до `api.figma.com` сам.
3. **Дозволені хости середовища** (Settings середовища → Network, або Claude додає через `update_environment` із твоїм підтвердженням): `api.figma.com`, `figma-alpha-api.s3.us-west-2.amazonaws.com`, `s3-alpha-sig.figma.com`.
4. **Перевірка:** `python3 shared/figma-tools/figma_read.py me` має вивести ім'я й email. Далі `comments <посилання на файл>` і `render <посилання> <id вузлів>`.

Обмеження, про які треба знати:
- Файл читається, лише якщо акаунт токена має до нього доступ. Якщо команду Figma замкнено (після завершення пробного періоду), доступ може зникнути, поки її не розблоковано.
- Ліміт запитів Figma (429) на безкоштовному місці суворий: не робити пачки запитів поспіль, скрипт сам чекає й повторює.
- Токен не показує список файлів команди (немає права `projects:read`): ключі файлів беруться з посилань.
- **Запускати плагін-генератор макета може лише людина** у Figma Desktop (Plugins → Development → Import plugin from manifest), у вебверсії локальні плагіни не працюють. Figma MCP на плані Starter має дуже малий ліміт викликів.

## 2. Webflow
- Підключити коннектор Webflow (MCP) до акаунта Claude і авторизувати потрібний сайт. Усі операції (сторінки, елементи, стилі, ассети, скрипти, публікація) йдуть через Data API без Designer.
- Для перевірки живої сторінки дозволити хост `<сайт>.webflow.io` і `cdn.prod.website-files.com`.
- Обмеження API (вільний кастомний код не пишеться, ліміти скриптів, публікація раз на хвилину): див. «Обмеження інструментів» у кореневому `CLAUDE.md`.

## 3. Інші хости, які бувають потрібні
- Google Drive (матеріали клієнта): `drive.google.com`, `drive.usercontent.google.com`, `lh3.googleusercontent.com`.
- Сторінки колег і матеріали для перелінковки: `special.ain.ua`, `ain.ua`, `i.ain.ua`, `cdn.ain.ua`.
- Хост додаємо тільки на конкретну потребу.

## 4. Інше в середовищі
- Playwright і Chromium вже встановлені (`require('playwright')`), нічого ставити не треба. Збірка кодових файлів використовує `npx terser` (підтягується сама).
- Репозиторій для цієї роботи має бути підключений до сесії при її старті (або через `add_repo`, якщо він публічний чи доступ до нього вже дозволено).
- Ліцензійні шрифти клієнтів у репозиторій не комітимо.
