# Перевірки лендінгів (Playwright Chromium)

Усі скрипти запускаються з кореня сайту (де `index.html`) або з `ROOT=<папка>`; для живої сторінки — `URL=<адреса>`.
Префікс класів і назва проєкту задаються змінними: `PREFIX=<prefix>` (за замовчуванням `mz`) і `NAME=<name>` (за замовчуванням `mazda`); `live_footer.js` додатково бере `VERSION=vN` (без неї підходить будь-яка версія `<name>-anim-vN`). Приклад: `PREFIX=kr NAME=kredo URL=https://… node shared/qa/live_footer.js`.
Самі перевірки писалися під блоки Mazda (полароїди `[data-shot]`, зупинки маршруту, «Керованість», завіса й штамп): для нового проєкту назви блоків у них підставити свої або вимкнути непотрібні кроки.
Playwright і Chromium у середовищі вже встановлені (`require('playwright')`, нічого не ставимо).

| Скрипт | Що перевіряє |
|---|---|
| `mobile_desktop_check.js` | iPhone 13: зсув полароїдів при прокрутці вниз-вгору (має бути 0 px), горизонтальне переповнення, старт мобільного відео, зупинки маршруту; десктоп 1440/1920: блок «Керованість» |
| `intro_probe.js` | заставка: чи є кадри, де видно сторінку до помаранчевої завіси (має бути 0), приземлення штампа без стрибка (`DELAY=700` імітує повільне завантаження скрипта) |
| `shake_probe.js` | чи не відкриває трясіння завіси сторінку по краях (щілина має бути 0 px) |
| `parallax_check.js` | чи немає паралаксу від скролу у полароїдів на десктопі |
| `live_footer.js` | жива сторінка (`URL=`): кінцевий блок, картинки, `target=_blank`, переповнення, скріншоти на десктопі й телефоні |

Чого вони не бачать: дрижання на справжньому екрані (там кадри малюються асинхронно), справжній iOS Safari.
Це завжди відкрита перевірка для користувача.
